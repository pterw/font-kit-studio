# Decisions and deviations

IDs are stable; gaps are retired process entries.

| ID | Decision / deviation | Basis | Cost if wrong |
|---|---|---|---|
| D001 | Ruling: use supplied v0.1.1 HTML as preserved baseline; characterize existing features and fix actual defects, without reconstructing v0.1.0. | Input already implements rows; no original v0.1.0 was supplied. | A genuine earlier baseline would require a separate import. |
| D004 | Ruling: map historical /mnt/data paths to this repository and supplement structural checks with behavioral tests. | Windows workspace; runtime evidence tests the specification. | Verification tooling differs from historical environment. |
| D009 | Ruling: keep filename font_kit_studio_v0.1.1.html and composition JSON version 0.1.1; add optional `live` field. | README, tests, bookmarklets and existing exports reference both; additive field keeps old imports valid. | A later rename/version bump needs a migration note. |
| D009a | Extension of D009: the visible Studio title and eyebrow also stay "v0.1.1" (asserted by the legacy suite) although the release content is v0.2.0. A rename/bump is a separate decision. | Compatibility with existing tests, links and bookmarks. | Users may be confused by the version label. |
| D010 | Evidence limitation: Firefox was not available in the development environment and Playwright browser downloads were not permitted, so acceptance ran Chromium only via FKS_ENGINES. The default engine list remains chromium,firefox; Firefox is to be verified in CI. | Browser inventory of the development environment. | Firefox-specific regressions stay undetected until the first Firefox run. |
| D016 | Ruling: three intentional departures from the Spec: (a) auto-discovered targets persist DOM-path selectors (Spec 2.3) for zero-hook use, labelled unstable; (b) pop-out mode lets the bridge draw its own outline (Spec 2.4) because Studio cannot overlay a separate window; (c) structural moves of target elements (Spec 19 defers arbitrary DOM mutation), bounded by guards and reversible reset. | Requirements: zero-hook editing, separate-window preview, reorganizing buttons/cards; plan Addenda 1-2. | If the Spec's stricter boundary is wanted later, disable auto selectors in sync output and gate moves behind a flag. |
| D017 | Ruling: Task C kept Studio's last acknowledged composition tokens in memory only (not in the `live` JSON), so they did not survive a Studio reload or JSON import. Task F added them to the validated `live` field. | Avoided a schema change in the first Studio change; the silent-overwrite defect is fixed regardless. | Before Task F, tokens had to be re-synced with the composition sync button after a Studio reload. |
| D019 | Ruling (Task E): bulk manifests omit `containers` and empty `siblings` over 100 children; sibling-only registrations are `arrangementOnly` and excluded from hit-testing; content-model move guard; strict percent-escape allow-list for font URLs; reference-counted `imports`. Recorded as plan Addendum 3. | Verified 8.36 MB `design:ready` on a 718-target page (quadratic `containers`); `li` text selecting whole `ul` and `summary` not toggling in Select mode. | Studio must fetch arrangement from selected/applied manifests; a page with >100 siblings shows no sibling list until selection. |
| D019a | Correction to D019: after the later amendment, bulk manifests omit both `containers` and `siblings` entirely (no 100-child threshold). Plan Addendum 3 is authoritative. | Final review consistency check. | None. |
| D020 | Ruling (Task F): saved css-order moves persist in Studio's saved overrides, the `live` JSON and the synced CSS, and Reapply replays them as css-order moves. arrangementOnly targets are excluded from the "Connected (N targets)" count as well as the default list. Extended in Addendum 7: DOM-strategy moves are saved too, as `live.structure` in Studio's saved state and the `live` JSON (never in the CSS file), and Reapply replays them in order after its resets. Only a user's DOM move adds a container to the saved order; a reset, a connect or Accept target state never adopts a container that only the page reordered (Accept keeps the saved containers the page still holds). A container is replayed only while it still holds one of its saved children. | Without it the synced overrides file silently loses `order` rules after a reload, and DOM moves were lost on reload (global rule 6). | A Move anyway move is saved but replayed without force, so the guard stops Reapply with the reason; mixing CSS order and DOM order in one flex container can replay by visual index; a bridge without `orderIds` cannot save DOM moves. |
| D021 | Closed in Addendum 7: composition `design:update` accepts an optional `fontStylesheets` list (the complete set, at most 16 allow-listed URLs), and Studio sends it after the user has asked for free fonts (D031). Originally deferred (Task F): the legacy composition `design:update` (⚡ Sync to Live App) sends font stacks as tokens without stylesheet URLs, so free fonts used only via composition tokens are not loaded in the target unless the app or the synced overrides import them. Contract gap, not a Task F defect. Candidate: optional `fontStylesheets: [url]` on composition updates (bridge + Studio). | Out of wave-2 scope; targeted live edits already carry `fontStylesheet`. | Composition-only token changes may render with fallback fonts in the target. |
| D022 | Ruling: recorded Spec departures in the implementation: `design:conflict` is expressed as `design:rejected` with `reason: "revision-conflict"`; `capabilities` reports `inspect, patch, typography, text, tokens, reset` (no `assets`); target `kind` is `text` or `image` only; `design:select-slot` is removed in favour of `design:selected`; `design:inspect`/`design:ping` are removed (unused, untested). The Spec file is supplied input and is not edited. | Message tabulation in sweep-v0.2.md; contract in the plan. | Integrators reading the Spec alone see stale message names; README documents the implemented protocol. |
| D023 | Ruling (Task D): the bridge rejects composition updates containing invalid token names or values (`design:rejected unsupported-value`) instead of dropping them silently; the legacy `fontkit:change` message still drops unsafe fonts silently and acks, because its legacy protocol has no rejection message. `targetId` stays in the composition slot payload as a no-op (bridge legacy tests rely on it). | Global rule 6 (no silent overwrite/drop) for the maintained path; legacy path frozen. | Integrators using `fontkit:change` get no error feedback. |
| D024 | Ruling (Task D): removed the bridge's uncalled public `registerElementTarget` method (Spec 4.2 level-2 explicit registration). Level-2 registration is served by author `data-design-*` attributes and `data-design-weights`; a JS registration API can return with tests when a consumer needs it. | Dead code with no caller, test or docs (sweep). | Integrators expecting `bridge.register()` per Spec 4.2 must use attributes. |
| D025 | Decision: the project is MIT licensed. `LICENSE` added with copyright holder "pterw" (the repository owner's GitHub handle); the holder line can be changed. Bundled logo outlines derive from SIL OFL 1.1 fonts, documented in `docs/assets/README.md`. | Licensing decision. | None. |
| D028 | Decision: Studio makes no external request on first load. Free Google Fonts load only after an explicit user action (Load free fonts, remembered per browser, or choosing a library family in the Live Target inspector); until then specimens use local fallback stacks. The frontend gate enforces this. | Privacy: opening Studio should not send the visitor's IP to a third party. | First-time visitors see fallback faces until they load fonts. |
| D029 | Decision: Font Kit Studio is a desktop-first tool. CI blocks on Chromium at the desktop profile only (frontend gate and test suite). Firefox and the phone and wide-touch profiles still run and report, but never fail CI. The v0.1.1 suite's own 390px assertions stay as they are. | Designers edit and export from desktop browsers; phone-width and Gecko differences are worth seeing but should not gate releases. | A Firefox- or phone-only regression can merge unnoticed unless someone reads the reports. |
| D030 | Decision: global rule 8 now allows a Vite integration written as a Node package with zero runtime dependencies, which runs the project's own Vite with the fontkit plugin added in memory (`npx fontkit`) or from `vite.config`. It is dev-only and refuses to run in a production build. Studio stays a single file and the bridge stays dependency-free; the Python dev server stays stdlib-only. | One-command setup for Vite and React projects; a Python-only server cannot add the bridge to a Vite dev server. | A second toolchain (Node) to test and release; the package must be kept free of runtime dependencies by review. |
| D031 | Decision: pressing Sync to Live App does not count as asking for free fonts. The composition update carries library-font stylesheets only after the user has pressed Load free fonts or picked a library family in the Live Target inspector; otherwise no stylesheet is sent, the page shows each font stack's fallback, and the Composer status says how to load them. | Global rule 7 (D028): the actions that count as asking are explicit and few. | A first-time Composer sync shows the target's own fonts until the user presses Load free fonts. |
| D032 | Decision: importing a composition JSON, or applying it with Sync or Reapply, does not count as asking for free fonts. Library-font stylesheets from imported overrides and tokens are sent to the target, and written as `@import` lines in the CSS tab and the synced file, only after the user has pressed Load free fonts or picked a library family in the Live Target inspector. | Global rule 7 (D028, D031): a JSON document can come from someone else, and the asking actions stay explicit and few. The ask is remembered per browser, so a returning user is not affected. | Importing a saved composition in a new browser shows each font stack's fallback in the target until the user presses Load free fonts. |
| D033 | Ruling (Addendum 7): three existing tests were changed with intended behaviour changes, and review found none hides a regression. `test_i2_studio_overrides_are_persisted_and_accept_is_explicit` pins the new banner wording (Accept replaces saved overrides, composition tokens and DOM order). `test_reapply_states_that_it_resets_a_dom_moved_arrangement` imports JSON without `live.structure`, because the export now holds the DOM move; a companion test covers the saved case. `MoveTests.test_ledger_structure_reports_changed_containers_and_reset_restores_the_order` expects `orderIds`. | AGENTS.md: changes to existing tests are recorded, not silent. | None. |
