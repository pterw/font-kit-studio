# Font Kit Studio 0.3.1 Implementation Plan

Status: complete (2026-10-08); merged as PR #15 and published as 0.3.1.
Implementation branch: `fix/localhost-cookies`.
Base: `7598ebb91eb6ca437df91b5e60c24b6387a79d09` (`origin/main` at plan creation).

**Goal:** an app used at `localhost` keeps its sign-in cookies when shown inside
Studio, through either the Vite command, the standalone plugin or the proxy.

**Architecture:** choose the advertised Studio and proxy host from the app URL.
For localhost origins, reserve both IPv4 and IPv6 loopback listeners on one port
before publishing the address. Preserve the existing IP-target behavior and
the bridge's origin-pinned message boundary.

**Tech stack:** Node built-ins only; the project's Vite 7 or 8; Python unittest
and Playwright. Supported Node lines and fixture matrix: D043.

## Binding host and listener contract

| App URL host | Advertised Studio and proxy host |
|---|---|
| `localhost` | `localhost` |
| `127.0.0.1` | Existing `127.0.0.1` behavior |
| `[::1]` | Existing IP-target behavior; no new hostname switch |

This table preserves IP-target behavior rather than promising a new IPv6
same-site feature. Tests characterize the existing IP cases first.

In Vite mode, the final Studio host must match the host-selection rule for
`server.resolvedUrls.local[0]`. Apply it to the command and to the user's
standalone `fontkitStudio()` plugin. Studio currently starts before Vite listens:
derive its host from Vite's resolved configuration, or delay Studio startup until
the app URL exists. The implementation must prove the final URL and handle
startup failure, shutdown and Vite configuration restart without leaking a server.
The command/plugin coexistence check must still produce one bridge tag.

In proxy mode the target is available before startup. Choose the advertised
hosts before starting either server. Preserve target path, query and fragment,
redirect rewriting, HTTP forwarding and WebSocket hot reload. Cookies ignore
ports; Set-Cookie passes through unchanged. App storage still belongs to the
proxy's origin and does not migrate from the app's usual port.

For each server advertised as localhost:

1. Bind `127.0.0.1` and `::1` on the same port before returning its URL.
2. With requested port zero, an IPv6 `EADDRINUSE` closes the provisional IPv4
   listener and retries another free port. Never publish a partly reserved port.
3. Only `EADDRNOTAVAIL` or `EAFNOSUPPORT` permits IPv4-only startup; prove the
   injected unavailable-IPv6 path. Other errors fail with cleanup.
4. A fixed busy port keeps the existing Studio fallback and terminal warning;
   the fallback must reserve both addresses when advertising localhost.
5. Closing shuts down both listeners, active HTTP connections and proxy upgrades.
6. Host and Origin checks remain correct for every accepted loopback alias,
   including the browser's normalized port-80 origin where already supported.

The injected bridge tag continues to take `data-allowed-origins` from
`studio.origin`. Plugin `checkLocalOrigin` and proxy `LOOPBACK_URL_HOSTNAMES`
already accept localhost; test that acceptance and the hostile alternatives.
No protocol message or trust rule changes.
