# R2 Engine: implementation plan (outline)

Status: **outline** (2026-10-03). Completed, then approved by the owner, after R1 merges.
Design: [typography system design](../specs/2026-10-03-typography-system-design.md),
section 2 items 1-3, 8-10, 13; section 4.2 and 4.3.

## Goal

The bridge can tell Studio which text styles a page uses and apply a role stylesheet it
builds itself, so the pairing UI (R3) has something real to work on. No new pairing UI in
this release: everything is testable on the R1 fixtures.

## Scope

In: text-style detection with a time budget; multi-page roles across visited routes; the
bridge-owned role stylesheet and its protocol messages; framework adapters (Bootstrap 5,
Bootstrap 4, React with CSS modules); honest-preview reports; a minimal Studio view that
lists detected roles (enough to test, not the R3 design).

Out: the font picker, candidates, scale and guardrails (R3); writing files (R4).

## Contract to write first (binding before any parallel work)

Protocol v1 gains additive messages, specified in this plan before Studio and bridge work
split (AGENTS.md, Rules of engagement):

- `design:detect` (Studio to bridge) and `design:detected` (bridge to Studio): groups with
  family, size, weight, case, tracking, element count, sample text, shared classes,
  near-duplicate flags, the page or route they were seen on.
- `design:roles-apply` (Studio to bridge): structured roles, each a validated selector plus
  allow-listed properties. Never raw CSS (global rule 5).
- `design:roles-applied` (bridge to Studio): the canonical stylesheet hash and, per role,
  how many elements kept another font and which selector won (honest preview).
- `design:roles-clear`: removes the stylesheet; the page returns to its exact prior state.

## Tasks (coarse; each splits into briefs when the plan is completed)

- [ ] **R2.1 Protocol contract.** Message shapes, limits, version handling, hostile cases.
- [ ] **R2.2 Detection.** Group visible text styles; `data-design-role` overrides; budget:
  several thousand text elements within a limit fixed here, without blocking the page.
- [ ] **R2.3 Role stylesheet.** The bridge builds one stylesheet from structured roles with
  the hardened selector grammar and value validators; clean undo.
- [ ] **R2.4 Framework adapters.** Bootstrap 5 (`--bs-*` variables, class-named roles),
  Bootstrap 4 (plain rules), React with CSS modules (hashed classes flagged unstable).
- [ ] **R2.5 Honest preview.** Count elements whose computed font differs from the role's,
  and name the winning selector.
- [ ] **R2.6 Multi-page roles.** Merge detection across routes visited in the session,
  including SPA route changes; flag selectors that match different styles on other pages.
- [ ] **R2.7 Fixtures.** Add the CSS-modules, Bootstrap 4, multi-page and large-page
  fixtures (spec 4.1).
- [ ] **R2 release point.**

## Exit criteria

- Detected styles match an expected list on every fixture.
- Applying then clearing roles leaves DOM and computed styles byte-identical to before.
- Hostile selectors and values from a fake Studio are rejected by the bridge.
- Detection stays within its budget on the large-page fixture.

## Open questions

1. The time budget for detection and the size of the large-page fixture.
2. How near "near-duplicate" is (size within 1 px? weight within 100?).

## Risks

- Detection quality on real sites is the product's credibility; mitigation: fixtures from
  real-world patterns, and every heuristic covered by an expected-list test.
- Computed-style reads on big pages are slow; mitigation: the budget test, chunked work.
