# Font Kit Studio v0.2.0 — Live Preview, Code View & Sync Implementation Plan

## Scope — 2026-10-02

Develop the tool so live edits in Studio show on a **localhost preview of a web app**, and Studio **shows the changed CSS and HTML code to sync or copy**. This adds the v0.2.0 bridge scope on top of the completed v0.1.1 responsive-row work.

The v0.1.1 responsive-row plan is complete (`2026-09-30-v0.1.1-responsive-rows.md`). The `main` base (`9205f8c`) already contains an unreviewed bridge prototype (iframe connector, `fontkit-bridge.js`, theater/device modes). This plan characterizes and hardens that prototype against `font-kit-studio-v0.2.0-design-bridge-protocol-v1.md` (the "Spec"), rather than rewriting it from scratch.

Baseline facts (direct source + runtime, 2026-10-02):

- Full suite 20/20 OK in Chromium; Firefox is **not installed** in this environment (D010).
- Defect: bridge routes `design:restore-text` to an undefined `handleRestoreText` → TypeError; Restore Page Text never works.
- Defect: bridge `registerElementTarget` re-captures `initialText` on every rediscovery, so originals are lost after the first text edit.
- Defect: bridge intercepts clicks (`preventDefault`) on every discovered link/button even when no Studio is connected — the instrumented app is unusable standalone.
- Defect: no origin/session validation on either side (Spec §15); all `postMessage` uses `"*"`.
- Defect: Studio's `sendDesignMessage` contains a misplaced anti-recursion block executed on every send.
- Defect: on connect Studio immediately broadcasts the preset composition and restyles the live app (Spec §16: never silently overwrite).
- Gap: overlays are drawn inside target DOM (Spec §2.4 requires Studio-owned overlays).
- Gap: no localhost preview server, no demo target app, no CSS/HTML change view, no copy/sync of changes.

## Goal

Studio connects to a bridge-instrumented localhost app, the user clicks any element in the live preview, edits typography/colour/alignment/text in a Live Target inspector, sees the change immediately in the preview, and sees the resulting **CSS overrides** and **changed HTML** in a code panel with **Copy**, **Download**, and **Sync to file** (dev server writes an overrides stylesheet the app links, so changes survive reload).

## Global constraints

- Studio stays one self-contained HTML file, no runtime dependencies. `fontkit-bridge.js` stays dependency-free. `scripts/serve.py` is optional dev tooling (Python stdlib only).
- Preserve Library, Composer, rows, presets, import/export, theater/device controls and all existing tests.
- Composition JSON `version` stays `0.1.1`; new `live` field is optional and additive (D009).
- No source-code rewriting of the target app (Spec §19 deferred). Sync writes only a separate overrides stylesheet path fixed on the server command line.
- Tests: Playwright Python via `tests/support.py` (`ENGINES`, `launch`, `route_virtual_origins`). Run here with `FKS_ENGINES=chromium FKS_CHROMIUM_EXECUTABLE=/opt/pw-browsers/chromium`.
- New regressions need a failing behaviour test before the fix; existing correct behaviour is characterized, never artificially RED.

## Protocol contract (binding for Tasks B, C, D)

All messages in both directions carry `protocolVersion: 1`. All except `design:bridge-ready` and `design:hello` carry the Studio-issued `sessionId`.

### Session and origin rules (Spec §15)

- **Studio** sets `expectedOrigin = new URL(targetUrl).origin` on connect. It accepts a message only when `event.source === iframe.contentWindow`, `event.origin === expectedOrigin`, `data.protocolVersion === 1`, and (`type === "design:bridge-ready"` or `data.sessionId === currentSessionId`). Studio posts with `targetOrigin = expectedOrigin` (`"*"` only if that origin is `"null"`).
- Studio creates a fresh `sessionId` (`fks-<random>`) for every handshake; it sends `design:hello` on `design:bridge-ready` and on iframe `load` (bridge answers every hello with `design:ready`).
- **Bridge** accepts `design:hello` only from `window.parent` (or `window.opener`) and, if `allowedOrigins` is configured (option or `data-allowed-origins="a b"` on its script tag), only from those origins; default allows any origin but **pins** it. A hello pins `studioSource`, `studioOrigin`, `sessionId` (a later hello from the same source replaces the session). Every other control message must match pinned source, origin and sessionId, else it is ignored. Bridge posts to `studioOrigin` (`"*"` only if it is `"null"`). `design:bridge-ready` goes to parent/opener with `"*"` and contains no page data.
- Before any hello the bridge does **not** intercept clicks or emit hover/selection.

### Studio → Bridge

| type | fields | behaviour |
|---|---|---|
| `design:hello` | `sessionId` | pin session; reply `design:ready` |
| `design:update` (targeted) | `sessionId, requestId, baseRevision, targetId, patch` | validate whole patch atomically, apply, reply `design:applied` or `design:rejected` |
| `design:update` (composition, legacy) | `sessionId, requestId, baseRevision, patch{tokens?,slots?,layout?}` and no `targetId` | existing slot/token behaviour; styles applied record into the change ledger; reply `design:applied` with `targetId: "global"` |
| `design:select` | `sessionId, targetId \| null` | set/clear selected target; `scrollIntoView({block:"nearest"})` if off-screen; reply `design:selected` |
| `design:mode` | `sessionId, mode: "select" \| "interact"` | `select` (default after hello): clicks on targets are intercepted and select; hover reported. `interact`: page behaves normally, no hover/select messages |
| `design:reset` | `sessionId, requestId, baseRevision, targetId?` | remove all overrides (styles and text) for the target, or for every target and token if absent; reply `design:applied` with `canonicalPatch: {}` and `reset: true` |
| `design:restore-text` | `sessionId, requestId?, baseRevision?` | restore original text of all targets, keep styles; reply `design:applied` (`targetId: "global"`) |
| `design:highlight` (legacy) | `sessionId, targetId` | treated as `design:select` |

### Targeted patch keys (validation → canonical value → CSS)

| key | accepted | canonical | applied CSS (inline, `!important`) |
|---|---|---|---|
| `fontFamily` | string 1–300 chars without `; { } < > \` or `url(` | trimmed string | `font-family` |
| `fontSize` | finite number 4–400 | rounded to 2 dp | `font-size: Npx` |
| `fontWeight` | finite number 1–1000 | integer; if target declares `constraints.fontWeights` (from `data-design-weights="400 600 800"`) the nearest allowed value | `font-weight` |
| `lineHeight` | finite number 0.5–5 | 3 dp | `line-height` (unitless) |
| `letterSpacing` | finite number −0.5–2 (em) | 4 dp | `letter-spacing: Nem` |
| `color` | `#rgb`, `#rrggbb`, `#rrggbbaa`, or `rgb()/rgba()/hsl()/hsla()` with only digits, `.`, `%`, `,`, `/`, spaces | lowercase | `color` |
| `textAlign` | `left center right justify start end` | same | `text-align` |
| `textTransform` | `none uppercase lowercase capitalize` | same | `text-transform` |
| `text` | string ≤ 5000, `kind:"text"` targets only | same | leaf element: `textContent`; otherwise first non-empty text node |

`null` for any key removes that override (restores the element's original inline value / original text). Unknown key → `unsupported-property` (`detail.property`). Invalid value → `unsupported-value` (`detail.property, requested`). Unknown target → `unknown-target`. `baseRevision !== revision` → `revision-conflict` (`detail.baseRevision, revision`). Malformed message → `invalid-message`. A rejected patch changes nothing. Each successful update/reset/restore increments `revision` by exactly 1.

### Bridge → Studio

- `design:bridge-ready {protocolVersion}`
- `design:ready {sessionId, revision, capabilities:{inspect,patch,typography,text,tokens,reset}, viewport:{width,height}, tokens:{css:{…}}, targets: TargetManifest[], changes: ChangeLedger}`
- `design:applied {sessionId, requestId, revision, targetId, canonicalPatch, target?: TargetManifest, changes: ChangeLedger, reset?: true}`
- `design:rejected {sessionId, requestId, revision, targetId?, reason, detail?}`
- `design:hover {sessionId, targetId|null, rect?, name?, role?}` — requestAnimationFrame-throttled, only when the logical target changes.
- `design:selected {sessionId, targetId|null, rect?, target?: TargetManifest}` — on click in select mode or `design:select`.
- `design:bounds {sessionId, targetId, rect}` — selected target geometry after scroll/resize/ResizeObserver, rAF-throttled.
- `design:targets {sessionId, targets}` — after MutationObserver discovers new targets (debounced ≥100 ms).
- `rect = {x, y, width, height}` in target viewport CSS pixels.

`TargetManifest = {id, role, name, kind:"text"|"image", tag, stable, selector, editable:{text,typography,color,alignment}, constraints?:{fontWeights?:number[]}, text (trimmed, ≤200 chars), computed:{fontFamily,fontSize,fontWeight,lineHeight,letterSpacing,color,textAlign,textTransform}}`. `stable` is true only for author-supplied `data-design-id`.

`ChangeLedger = {tokens:{"--name": value}, targets:[{targetId, selector, stable, name, role, declarations:{"font-size":"56px",…}, text: string|null, originalText, html}]}` — targets ordered by first change; entries with no overrides and unchanged text are omitted. `declarations` use CSS property names and values without `!important`. `text` is the current text only if it differs from the original. `html` is the element's cleaned `outerHTML`: bridge-added attributes (auto `data-design-*`) and bridge inline overrides removed (author `style` restored), current text kept.

Selectors: author id → `[data-design-id="…"]` (quotes/backslashes escaped). Auto targets: `#id` if the element has an id, else a path of up to 4 steps (`tag.class:nth-of-type(n)` joined by ` > `), stopping at an ancestor with an id. Bridge-originated original state (inline style, text) is captured once per element (WeakMap) and never re-captured.

### Dev server endpoints (Task A ↔ Task C)

- `GET /__fontkit/status` → `{"sync": bool, "overrides": "<repo-relative path>", "target": "<target base url>"}` (studio port only).
- `PUT /__fontkit/overrides.css` (studio port only), `Content-Type: text/css`, body ≤ 1 MiB; if an `Origin` header is present it must equal the studio origin. Atomic write to the configured path. → `{"ok": true, "bytes": n, "path": "…"}`; 403 on bad origin or sync disabled; 413 over limit.
- All responses `Cache-Control: no-store`. Missing configured overrides file is served as an empty `text/css` 200.

### Contract additions (binding for wave 2)

**Arrangement.** `TargetManifest` gains `arrangement: {containerKey, containerName, containerSelector, index, count, siblings:[{id, name, tag}], containers:[{key, name}]}`. Siblings are the element children of the target's parent (excluding script/style/template/link/meta and bridge nodes); each is registered (auto if needed) so it has an id. `containerKey` is the container's `data-design-id` if present, else a bridge-assigned `container:<n>` stable for the session. `containers` = candidate destinations: elements with `data-design-order-container="true"` plus every element that is the parent of ≥ 2 registered targets.

`design:move {sessionId, requestId, baseRevision, targetId, to}` where `to` is exactly one of `{index:n}` (0-based within the current parent), `{before:targetId}`, `{after:targetId}`, `{container:key, index?:n}` (default: append). Reject `unsupported-value` for out-of-range indices, unknown containers, moving into itself/its descendants, or into void/replaced elements; `unknown-target` for unknown ids; same revision rules as updates. Success → `design:applied` with `canonicalPatch:{move:{container:key, index:n}}`, a refreshed `target`, `changes`.

`ChangeLedger` gains `structure:[{containerKey, selector, stable, name, html, order:[names]}]` for containers whose child order differs from their original (originals captured once). `html` is the cleaned container `outerHTML` (bridge attributes and inline overrides stripped throughout). `design:reset` with `targetId` also returns that target to its original parent/position when possible; reset-all restores every original order.

**Pop-out window.** `design:mode` gains optional `overlay: boolean` (default false). When true the bridge draws its own non-interactive hover/selection outline (pointer-events none, removed when false or on a new session). The bridge accepts `design:hello` from `window.opener` as well as `window.parent` (unchanged rule) and posts to whichever source pinned the session.

**Font stylesheets.** Targeted patch key `fontStylesheet`: `null` or an `https://fonts.googleapis.com/css2?…` URL (query limited to `family=`, `display=`, `text=` params with safe characters) or `https://use.typekit.net/<6–10 alnum>.css`. Bridge injects one `<link rel="stylesheet" data-fontkit-font>` per distinct URL into the target `<head>` and records it in `ChangeLedger.imports` (ordered, unique). Reset-all removes injected links and clears `imports`. Studio's CSS tab emits `@import url("…");` lines first.

## Addendum 2 — UX-safety guardrails and positioning (2026-10-02)

**Move guardrails (Task E bridge + Task F Studio, binding).**
- `TargetManifest.arrangement` gains `cssOrderAvailable: boolean` (parent computed `display` is flex/inline-flex/grid/inline-grid) and `frameworkManaged: null | "react" | "vue" | "svelte" | "unknown"` (detected on the element or nearest ancestor: `__reactFiber$*`/`__reactProps$*`/`_reactRootContainer` keys, `__vue__`/`__vueParentComponent`/`__vue_app__`, `__svelte_meta`/`__svelte*` keys).
- `design:move` gains optional `strategy: "dom" | "css-order"` (default `"dom"`). `css-order` (only when `cssOrderAvailable`) assigns `order` to every element sibling (recorded in the ledger as declarations and emitted in CSS), leaving the DOM untouched. With `"dom"` the bridge runs pre-move checks and rejects with `unsupported-value` + `detail.guard` when the move would: take a form-associated control (input/select/textarea/button/fieldset/output, or an element containing one) out of its form owner; separate a radio input from its same-`name` group container; break a `label[for]`, `aria-controls`, `aria-labelledby` or `aria-describedby` reference that resolves today but would not (scoped by `getRootNode`) afterwards; or touch a `frameworkManaged` subtree unless `force: true` (for frameworks, the guard is a warning-level rejection the user can override).
- After every applied update/move the bridge listens for `error`/`unhandledrejection` in the target for 1000 ms and posts `design:warning {sessionId, requestId, targetId, kind:"runtime-error", message}` for each (message ≤ 300 chars).
- Studio: Arrange section shows a "Move strategy" toggle when `cssOrderAvailable` (default CSS order for framework-managed parents), surfaces guard rejections with the reason and an explicit "Move anyway" only for framework guards, and shows runtime warnings in the status area and code panel.

**README positioning (Task D).** Add "Why fontkit" and a short FAQ answering: what it is vs visual builders / component workbenches / DevTools-style extensions / code-writing editors (no unverifiable competitor claims), how click-and-go it is (one script tag, bookmarklet, pop-out, extension roadmap), and how UX safety works for structural moves (guards, CSS-order strategy, runtime error capture, Interact mode testing, snippets you apply yourself).

## Addendum 3 — contract amendments from Task E review (2026-10-02, binding)

- **Bulk manifests.** In `design:ready` and `design:targets`, `arrangement.containers` and `arrangement.siblings` are both omitted (`containerKey`, `containerName`, `index`, `count`, `cssOrderAvailable`, `frameworkManaged` stay). Amended after the Task E re-review measured 15.8 MB with 2000 targets under the earlier 100-sibling cap. `design:selected`, `design:applied` and any single-target manifest always carry full `siblings` and `containers`. Studio takes Arrange data only from selected/applied manifests.
- **Arrangement-only targets.** Elements registered only because they are siblings of a target carry `arrangementOnly: true` in their manifest. They are excluded from hover and click hit-testing (the next author/semantic target ancestor, or nothing, wins) and from Studio's default target list, but remain addressable by id (sibling list, `design:select`, `design:move`).
- **Content-model guard.** `design:move` (strategy `dom`) also rejects with `detail.guard: "content-model"` when a block-level element (div, p, section, article, aside, header, footer, nav, ul, ol, table, form, figure, h1-h6, blockquote, details) would be placed inside `p`, `h1`-`h6`, `span`, `a`, `button`, `label` or `summary`. Not overridable by `force`.
- **Font stylesheet URL.** Percent-escapes in `family=`/`text=` are limited to `%20 %2B %2C %3A %3B %40` (space, plus, comma, colon, semicolon, at); anything else is `unsupported-value`.
- **Container names.** `containerName` prefers `data-design-name`, then `aria-label`, then the first heading text inside (≤40 chars), then `#id`, then `tag.class`.
- **Imports.** `ChangeLedger.imports` lists only stylesheets still referenced by at least one target (reference-counted); `null` or reset releases.
